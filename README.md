# Близко — контактная книга

Django-приложение для ввода, хранения, импорта, анализа и экспорта контактных данных.
**Вариант 04: информация о контактах в XML.** Дополнительно поддерживается JSON с той же структурой данных.

![Интерфейс контактной книги «Близко»](docs/screenshot.png)

## Возможности

- Русскоязычный адаптивный интерфейс: контакты, создание записи, импорт и библиотека файлов.
- Сохранение введённого контакта в отдельный XML- или JSON-файл.
- Импорт нескольких контактов из одного файла. Исходный файл сохраняется целиком, без изменения содержимого.
- Валидация формы, синтаксиса файла, структуры и каждой записи. Проверка выполняется на сервере, даже если JavaScript отключён.
- Автоматическое чтение **всех** XML/JSON-файлов из папки хранилища. Повреждённый файл не мешает показать остальные: для него отображается предупреждение.
- Поиск по всем полям, фильтры по группе и формату, сортировка по фамилии, пагинация по 12 контактов.
- Анализ данных: общее число контактов, количество файлов, распределение по форматам и группам.
- Скачивание оригинального файла, преобразование отдельного файла между XML/JSON и общий экспорт.
- Явные сообщения, если файлов нет, поиск ничего не нашёл, данные невалидны или файл недоступен.
- Готовые примеры и автоматические тесты, запускаемые также в GitHub Actions.

## Быстрый запуск

Нужен Python **3.12 или новее**. Проверено на Python 3.14.

```bash
git clone https://github.com/danya2271/xmlsite.git
cd xmlsite
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py runserver
```

Откройте **http://127.0.0.1:8000/**.

В Windows для создания окружения используйте `py -m venv .venv`, для активации в PowerShell — `.venv\Scripts\Activate.ps1`.

Контакты хранятся в файлах, а сообщения — в подписанных cookie. База данных, миграции, Node.js, CDN и внешние сервисы для запуска не требуются. Папка `data/contacts/` создаётся автоматически при первом обращении, если её нет.

## Проверка задания

1. На главной странице пустого проекта отображается сообщение об отсутствии файлов.
2. Нажмите **«Добавить контакт»**, заполните форму, выберите XML и сохраните. Запись появится в таблице, а файл — в `data/contacts/`.
3. Попробуйте неправильный email, короткий телефон или будущую дату рождения: форма покажет ошибки, файл не создастся.
4. Откройте **«Импорт»**, выберите `examples/contacts.xml`. В таблицу добавятся три контакта. Импорт `examples/contacts.json` добавит ещё два.
5. Загрузите повреждённый XML, JSON с неверными полями или файл другого расширения. Появится сообщение об ошибке; невалидный файл не останется в хранилище.
6. Проверьте поиск, группы, форматы, скачивание файлов и **«Экспорт всех»** в обоих форматах.

Демонстрационные данные вымышлены. Импорт **добавляет** записи: повторный импорт создаст новый файл и повторные контакты. Дедупликация не выполняется.

## Структура данных

XML — основной формат:

```xml
<?xml version="1.0" encoding="utf-8"?>
<contacts version="1">
  <contact>
    <first_name>Анна</first_name>
    <last_name>Соколова</last_name>
    <phone>+7 (900) 123-45-67</phone>
    <email>anna@example.com</email>
    <company>Студия Форма</company>
    <city>Екатеринбург</city>
    <category>work</category>
    <birthday>1998-04-12</birthday>
    <notes>Обсудить новый проект.</notes>
  </contact>
</contacts>
```

Эквивалентный JSON:

```json
{
  "version": 1,
  "contacts": [
    {
      "first_name": "Анна",
      "last_name": "Соколова",
      "phone": "+7 (900) 123-45-67",
      "email": "anna@example.com",
      "company": "Студия Форма",
      "city": "Екатеринбург",
      "category": "work",
      "birthday": "1998-04-12",
      "notes": "Обсудить новый проект."
    }
  ]
}
```

### Проверка полей

| Поле | Требования |
| --- | --- |
| `first_name`, `last_name` | Обязательные, до 80 символов: буквы, пробелы, дефис, апостроф. |
| `phone` | От 7 до 15 цифр; допустимы начальный `+`, пробелы, скобки, дефис; максимум 30 символов. |
| `email` | Корректный email, максимум 254 символа. Нужен хотя бы один из `phone` / `email`. |
| `company` | Необязательное, до 120 символов. |
| `city` | Необязательное, до 100 символов. |
| `category` | `work`, `friends`, `family`, `other`. При отсутствии в импортируемой записи — `other`. |
| `birthday` | Необязательное, `YYYY-MM-DD`, с 01.01.1900 до текущей даты. |
| `notes` | Необязательное, до 1000 символов. |

Все значения полей контакта — **строки**. Необязательное поле можно опустить или передать пустой строкой, кроме `category`: если оно передано, значение должно быть из списка. В форме группа выбирается обязательно.

Для файла обязательны версия `1` и непустой список контактов. Неизвестные поля, повторяющиеся JSON-ключи/XML-элементы, вложенные поля, XML-атрибуты контактов и несовместимые с XML символы Unicode отклоняются. JSON-версия должна быть целым числом `1`, а не строкой или логическим значением.

**Ограничения:** UTF-8 (допускается BOM), до **1 МиБ (1 048 576 байт)** и **500 контактов** на файл. Если один контакт невалиден, отклоняется весь импорт — частичного сохранения нет. Общий экспорт имеет те же ограничения, чтобы результат можно было импортировать обратно; при превышении скачайте исходные файлы по отдельности. При повреждённых исходных файлах общий экспорт отменяется с предупреждением, чтобы не выдавать неполный результат.

## Хранение и безопасность

- Загруженное имя используется только для проверки расширения; имя на диске всегда генерируется: `<uuid4>.xml` или `<uuid4>.json`.
- Запись проходит через временный файл. После полной проверки выполняется атомарное переименование. При ошибке временный файл удаляется.
- На Unix новые папки создаются с правами `0700`, файлы — `0600`.
- Файлы читаются с ограничением размера. Подмена расширения не обходит проверку синтаксиса и данных.
- XML разбирается библиотекой `defusedxml`: запрещены DTD, сущности и внешние ссылки, включая XXE.
- При скачивании запрещены обход каталогов и чтение символических ссылок. Хранилище не раздаётся как `/media/` или статика.
- Формы защищены CSRF. Шаблоны экранируют пользовательский текст; JavaScript не вставляет имена файлов как HTML.
- Страницы с контактами и скачиваемые данные отправляются с `Cache-Control: private, no-store`.
- Реальные загруженные данные, `.env`, окружение и временные файлы исключены из Git.

Приложение **учебное, однопользовательское и без авторизации**. Для локального использования запускайте на `127.0.0.1`. Не публикуйте сервер с реальными контактами в интернете без добавления аутентификации, разграничения доступа и HTTPS. Публикация кода на GitHub не означает развёртывание сайта.

## Настройки

Настройки читаются из **переменных окружения**. `.env.example` — только пример; автоматического чтения `.env` нет.

| Переменная | Значение по умолчанию |
| --- | --- |
| `DJANGO_DEBUG` | `true` для локальной разработки. |
| `DJANGO_SECRET_KEY` | Только локальный ключ; при `DEBUG=false` обязательно задайте собственный. |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1,[::1]`, список через запятую. |
| `CONTACTS_STORAGE_DIR` | `<корень проекта>/data/contacts/`. Желательно указывать абсолютный путь. |

Например, для отдельного хранилища:

```bash
CONTACTS_STORAGE_DIR=/tmp/my-contactbook python manage.py runserver
```

При подготовке к развёртыванию задайте секрет, выключите отладку, настройте HTTPS и разрешённые хосты. Используйте WSGI/ASGI-сервер вместо `runserver`, настройте раздачу статики после `python manage.py collectstatic` и резервное копирование папки контактов. Ограничьте размер тела запроса в reverse proxy: проверка размера в Django не заменяет ограничение входящего трафика. Автоматическое принудительное перенаправление на HTTPS не включено: его необходимо настроить на уровне сервера или Django.

## Маршруты

| Адрес | Назначение |
| --- | --- |
| `/` | Все контакты, поиск, статистика и библиотека. |
| `/contacts/new/` | Создание контакта. |
| `/import/` | Загрузка и проверка файла, описание формата. |
| `/files/<имя>/` | Скачать оригинал; `?format=json` или `?format=xml` — конвертация. |
| `/export/xml/`, `/export/json/` | Общий экспорт всех контактов. |
| `/examples/xml/`, `/examples/json/` | Скачать пример. |

Фильтры главной страницы: `q`, `category`, `format`, `page`. Например: `/?q=Анна&category=work&format=xml`.

## Проверки

```bash
python manage.py check
python manage.py test --verbosity 2
```

Тесты используют временные папки, не изменяют рабочие контакты и не требуют базы данных. Проверяются формы, XML/JSON round-trip, XXE/DTD, дубликаты ключей, лимиты, кодировки, Unicode, отсутствие частичного импорта, очистка невалидных файлов, уникальность имён, обход путей, симлинки, ошибки файловой системы, CSRF, XSS, поиск, пагинация и экспорт.

GitHub Actions выполняет проверки на Python 3.12, 3.13 и 3.14 при каждом push и pull request.

